# Fiche de décisions

| Choix | Options envisagées | Choix retenu et justification | Validé par l'auxiliaire (date) |
|---|---|---|---|
| Domaine | Finance, automobile (prix des voitures d'occasion), éducation | Éducation : c'est un sujet qui nous concerne directement comme étudiants. Un utilisateur peut estimer l'effet de ses habitudes (heures d'étude, sommeil, examens pratiqués) sur sa performance. | 2026-11-12 |
| Jeu de données | CarDekho (Car details v3), Student Performance | Student Performance (Kaggle) : 10 000 lignes, 5 caractéristiques (4 numériques, 1 catégorielle), cible numérique claire, licence libre (« Anyone is free to share and use the data »), aucune donnée personnelle. CarDekho écarté : plusieurs colonnes numériques sont stockées en texte avec leurs unités (`mileage`, `engine`, `max_power`, `torque`) et il y a des valeurs manquantes. Le nettoyage aurait pris une grande partie des 8 h, au détriment de l'interface. | 2026-11-12 |
| Doublons | Supprimer, conserver | Conservés (127 lignes). Les entrées n'ont que 64 800 combinaisons possibles ; ~730 répétitions sont attendues par hasard sur 10 000 lignes et 792 sont observées : ce sont vraisemblablement des étudiants distincts. Limite : une même ligne peut se trouver en entraînement et en test (1,3 % des données). | |
| Encodage | `.map`, `get_dummies` | `Extracurricular Activities` encodée Yes → 1, No → 0 avec `.map` : variable binaire, une seule colonne suffit. L'encodage est enregistré dans les métadonnées JSON pour que l'interface l'applique de la même façon. | |
| Séparation | 80/20, 70/30 | 70/30 avec `random_state=42` : 3 000 lignes de test donnent une mesure d'erreur plus stable, et 7 000 lignes suffisent largement pour une régression linéaire. Graine fixée pour la reproductibilité. | |
| Cible et métrique | MAE, RMSE, R² | `Performance Index` (régression, 10 à 100). Métrique principale : MAE, lisible directement en points d'indice (« le modèle se trompe en moyenne de X points »). R² en complément. MAE calculée avec NumPy (`mae_numpy`) et vérifiée contre scikit-learn par un test. | 2026-11-12 |
| Référence | Moyenne, médiane | `DummyRegressor(strategy="mean")` : prédit toujours la moyenne. MAE de 16,24 points, R² ≈ 0 : c'est le score à battre. | |
| Modèle | Régression linéaire multiple, forêt aléatoire, deux régressions (une par valeur d'activité parascolaire) | Régression linéaire multiple : simple, coefficients interprétables, adaptée à une cible numérique. Comparaison sur le même ensemble de test : un seul modèle a une MAE de 1,6090 et deux modèles par groupe ont une MAE de 1,6090 (R² de 0,989 dans les deux cas). Le gain est nul, donc on garde **un seul modèle**, plus simple. Forêt aléatoire écartée : la relation observée est presque linéaire (voir `figures/exploration.png`). | 2026-11-12 |
| Sauvegarde du modèle | Ré-entraîner à chaque lancement, sauvegarder | Script `src/entrainement.py` lancé une fois : modèle en `joblib`, métadonnées en JSON (colonnes, intervalles, catégories, encodage, métriques). `main.py` recharge le modèle sans ré-entraîner, comme l'exige l'énoncé. Les fichiers générés ne sont pas versionnés : un modèle `joblib` dépend de la version de scikit-learn installée. | |
| Bornes des saisies | Bornes logiques (0 à 24 h, 0 à 100), minimum et maximum observés | Minimum et maximum observés dans les données (par exemple 1 à 9 h d'étude). Hors de ces intervalles, le modèle extrapolerait sans aucune donnée pour le soutenir. | |
| Technologie d'interface | Tkinter, Streamlit | Tkinter : inclus avec Python (aucune dépendance de plus), application locale sans serveur web, et intégration de Matplotlib documentée (`FigureCanvasTkAgg`). Streamlit aurait été plus rapide à mettre en page, mais il impose un serveur et un navigateur. | 2026-11-12 |
| Graphique de l'interface | Importance des variables, prédit contre réel, effet d'une variable | Courbe de l'indice prédit selon les heures d'étude (1 à 9 h), les autres saisies restant fixes, avec le cas de l'utilisateur en rouge. L'utilisateur voit l'effet concret d'une heure d'étude de plus. Le graphique prédit contre réel est gardé pour la présentation (`figures/`). | |
| Historique | CSV, JSON | CSV : une ligne par prédiction, lisible dans un tableur, ajouté avec `csv.DictWriter` en mode `"a"`. | |
| Outil du chapitre 7 | Décorateur, générateur, lambda | Décorateur `chronometre` sur `Modele.entrainer` : il mesure la durée sans modifier la méthode, et la durée est enregistrée dans les métadonnées. Une lambda sert aussi de clé de tri pour les valeurs des catégories. Générateur écarté : le CSV (10 000 lignes) tient facilement en mémoire. | |
| Avertissement | Afficher, ne pas afficher | Domaine éducation, qui n'est pas dans la liste des domaines sensibles de l'énoncé. Le README précise toutefois que les données semblent synthétiques et que le modèle ne s'applique pas à de vrais étudiants. | |
| Unités affichées dans l'interface | Aucune unité, par jour, par semaine | Bornes en gris à côté de chaque champ, avec l'unité : heures d'étude **par semaine** (1 – 9), sommeil **par jour** (4 – 9), examens pratiqués **par semaine** (0 – 9, **entier** uniquement : on ne pratique pas 2,5 examens), notes antérieures sur 100. Les champs qui acceptent les décimales affichent leurs bornes avec une virgule (« 1,0 – 9,0 »). Choix de l'équipe pour que l'utilisateur sache quoi saisir ; le graphique et la figure d'exploration disent aussi « par semaine ». | |
